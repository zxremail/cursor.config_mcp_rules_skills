# 价值观礼物文案

把用户提供的**工作案例**写成可直接复制的五段礼物文案。称呼一律用「您」。

**禁止**套用 `ai-work-result-report` 的「使用场景 / 如何使用 / 输出成果 / 成果证明链接」。

## 硬性顺序

1. **先收案例，再写文案。** 用户还没给出具体事例（事项、动作、结果；或飞书/Wiki 链接；或周报摘录）时：只追问案例，不填写任何一段。
2. 案例里有飞书 `/docx/`、`/wiki/` 链接时：先读 `lark-doc` 与 `lark-shared`，再 `lark-cli docs +fetch --doc "<URL>" --as user`。Wiki 类型不明时按 `lark-wiki` 取节点后再 fetch。
3. **只写案例里已有的事实。** 禁止编造指标、通过率、时长、结论或链接。
4. 按下方模板输出；**五段都必须有正文**，禁止空段。

## 输出模板（标题逐字使用）

只输出下面这一块纯文本（标题与空行保持原样），便于整段粘贴。不要加 Markdown 标题、表格或 checklist。

```text
我给您发送礼物的原因是这样的：

{原因}

在了解了事情背景后，您确定了以下目标：

{目标}

为了达成目标，您做了这些事：

{行动}

多亏您的积极行动，达成以下结果：

{结果}

从您的行动中，我学到了：

{收获}
```

有证明链接时，写在「结果」段末尾：`证明链接：<用户给的原始 URL>`。

## 各段写什么

| 段 | 写 | 不写 |
|---|---|---|
| 原因 | 为何此刻送礼：事项 + 对方体现的价值取向（攻坚、协同、闭环、对结果负责等），1 小段 | 空着；复述后文细节 |
| 目标 | 对方当时要达成的具体目标，1 小段 | 旁观者的目标；空泛口号 |
| 行动 | 对方实际做的事，按时间/因果压缩成 1 段 | 案例没有的步骤 |
| 结果 | 可核对的结果；有数字用案例中的数字 | 把行动再讲一遍；虚构量化 |
| 收获 | 旁观者从**行为方式**学到的可迁移一点 | 技术结论复读；「很敬业」空话 |

## 自检（写完后在回复末尾用 3～5 条说明，不要放进粘贴正文）

- 五段标题与模板一致，且每段都有正文
- 事实均可回溯到用户案例或 fetch 到的文档
- 「收获」不是「结果」的改写
- 称呼为「您」
- 有链接则出现在结果段

## 示例（输入 → 输出形态）

输入：USB3380 上 USBTMC 不通；硬件定位到内部寄存器/BAR 异常；改 EEPROM、把 EP0 放到内核；插拔 100 次通过；给了飞书验证文档。

输出要点：原因写「卡点上把链路做成可发版」；目标写打通 USBTMC 并验证可靠性；行动写协同硬件、EEPROM、内核 EP0、插拔/长稳；结果写案例中的通过数据 + 证明链接；收获写「先锁根因再换路径，用可量化验证收口」。
