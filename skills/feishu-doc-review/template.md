# 评审意见书脊（必须按此顺序产出）

文首 YAML 式引用块必填源链接、revision（或变更日志版本）、输出方式。有配套文档则加一行。

```markdown
# {源文档标题} · 评审意见

> **源文档**：[{标题}]({飞书 URL})
> **文档 revision**：{revision_id 或变更日志版本}
> **评审输出方式**：独立整理，不修改源文档
> **配套参考**：[{标题}]({URL})   <!-- 没有则删此行 -->

## 1. 总体评价

{2～6 句：骨架是否清楚、最大硬伤、建议决议（如有条件通过 / 先收敛矛盾 / 不能当基线）。}

| 证据维度或章节域 | 强度或成熟度 | 说明 |
|------------------|--------------|------|
| … | 强 / 中 / 弱 / 无 | … |

**建议：{一句话下一步}。**
```

### 填写约束

- P0 至少尝试列出；若确无内部矛盾/证伪/自洽失败，写明「未见 P0」及依据，不要空着。
- 「优先改三件事」必须能独立执行，不要复述全文。
- 短摘要不含 Markdown 表、不含 Mermaid。
- 领域专节标题自拟，但不得删掉上面 1～7。
