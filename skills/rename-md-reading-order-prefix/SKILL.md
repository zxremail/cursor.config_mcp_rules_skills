# 按阅读顺序给 Markdown 加两位前缀

用户要求「重命名 md 文档」且未另给命名规则时，用本流程：按建议阅读顺序加 **两位数字前缀**，从 `00` 起。

## 命名规则

- 格式：`NN.原文件名.md`（`NN` 为 `00`、`01`、`02`…）。
- 索引文件排第一：

例如 `_INDEX_.md` 修改为 `00._INDEX_.md`

例如 `windows-linux-shared-overview.md` 修改为 `01.windows-linux-shared-overview.md`

- **不要**改文件名里原有的英文词干；只加前缀。
- 已有 `NN.` 前缀时：先问用户是重排还是跳过，禁止叠成 `01.01.foo.md`。
- 只处理用户点名的目录；**不要**给知识库根 `_INDEX_.md` 加前缀，除非用户明确要求改根索引文件名。

## 如何定顺序

1. 先读该目录的索引（`_INDEX_.md` / `00._INDEX_.md` / `*_INDEX_.md`）和文内「建议阅读顺序」。
2. **`00`**：该目录索引本身。
3. **`01` 起**：索引表里列出的专题，按表行顺序（或用户当场指定的顺序）。
4. 目录里还有索引表未列出的 `.md`：接到序号末尾（如会话笔记），或先问用户再排。
5. 表顺序与文内「建议阅读顺序」冲突时：以用户示例为准；否则以索引表行为准，并改文内建议顺序，使两者一致。

## 操作步骤

1. 列出目标目录全部 `.md`，排出 `旧名 → NN.旧名` 对照表，向用户确认前若用户已给范例则直接执行。
2. **先改磁盘文件名**，再改链接（禁止先全局字符串替换再改名）。
3. 更新所有指向这些文件的链接：同目录相对名、跨目录 `subdir/foo.md`、知识库根索引表、正文交叉引用。
4. 按 **`designated-knowledge-index`** 更新知识库 `_INDEX_.md` 的文档列路径。
5. 校验：每个 `](...md)` 目标文件存在；没有 `NN.NN.` 叠号。

## 改链接（防叠号）

对每个 `旧名 → 新名`，只替换**完整路径片段**，不要第二次再替换「旧名」子串。

错误：`windows-linux/foo.md` 已变成 `windows-linux/01.foo.md` 后，再把 `foo.md` 换成 `01.foo.md`，会得到 `windows-linux/01.01.foo.md`。

正确替换集合（每条只做一次）：

- `](旧名)` → `](新名)`
- `](目录/旧名)` → `](目录/新名)`
- 索引表显示名若等于旧文件名，一并改成新文件名
- 反引号路径 `` `目录/旧名` `` 若指文件，同样更新

根索引正文若写「专题索引是 `_INDEX_.md`」，改为实际新名（如 `00._INDEX_.md`）。

## 完成后

- 子目录索引表的链接改为带前缀的文件名。
- 索引里补上未列入、但已编号的文件（如 `11` 会话文）。
- 不改正文 `#` 标题（文件名序号 ≠ 章节序号）。
- 仅改文件名时不必重跑 `md-toc`；若改了标题再走 **`markdown-knowledge-maintain`**。

## 借口对照

| 借口 | 实际 |
|------|------|
| 先全局 replace 旧文件名更简单 | 会叠号；必须按完整路径替换一次 |
| 根 `_INDEX_.md` 也要 00 | 除非用户点名根文件；默认只改指定子目录 |
| 阅读顺序用改文件时间 | 用索引表 / 用户指定顺序 |
| 链接以后再改 | 改名与改链同一次完成 |
