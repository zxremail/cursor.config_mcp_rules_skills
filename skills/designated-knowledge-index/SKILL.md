## 1. 如何确定目录

- **知识库根目录**须由本仓库或用户**明确指定**，没有全局固定路径名；可能是 `docs/notes/`、`internal/`、`ai.cursor/` 等任意约定目录。
- 来源优先级（从高到低）：**用户当前消息中的路径** → **仓库规则/说明**（如 `AGENTS.md`、README、`.cursor/rules` 等写明的路径）→ **在仓库内搜索**常见索引（如 `**/_INDEX_.md`）并结合上下文推断。仍无法确定时，**先向用户确认路径**，勿臆造目录名。

## 2. 必须先做

1. 记知识库根为 **`<根>`**（即上述指定目录）。索引文件常见为 `_INDEX_.md`，子目录也可能是 `00._INDEX_.md`（阅读顺序前缀，见 **`rename-md-reading-order-prefix`**）。先找该层 `*_INDEX_.md`，**先 Read 该索引**，再按表内链接 Read 其它 `.md`；不要跳过索引、在 `<根>` 下凭猜打开文件。
2. 若 `<根>` 存在但无索引文件：列出该目录（及子目录）下 `.md`，优先读总览类文件名或用户点名的文档。

## 3. 索引表怎么用（存在索引时）

- 索引路径以项目约定为准；常见为 `<根>/_INDEX_.md`。
- **展示形式（推荐）**：用 Markdown **三列表格** — **文档** | **说明** | **提要**（表头以项目约定为准，常见即此三列）。
- **说明**：短标签（几字到十来字），扫读分类。
- **提要**：较长说明，含侧重点与检索词；可拆成多条「一句一义」，以清晰扫读为目标。
- **提要如何在表格里换行**：标准 Markdown **表格单元格内不能直接插入换行**；若要把提要写成多段，在 **提要** 列内使用 **HTML `<br>`** 分段（常见预览器 / GitHub 均支持）。可在表上方用 **blockquote** 一行说明「提要多条时用 `<br>`」，方便后续维护者照抄格式。
- **与分块词条的取舍**：若用户明确要求「仍以表格展示」，则保留表格，**不要**为换行而改成分块标题 + 列表；提要清晰度用 **`<br>` 分段** 解决。
- 先据此选题，再读正文核对。

## 4. 与仓库真源的关系

- 指定目录下多为人类整理笔记，**正误与领域依项目而异**；回答须与仓库内**源码、配置、脚本、日志**等可验证材料对照，冲突时以可验证真源为准。

## 5. 维护索引（用户让你改笔记时）

- 在 `<根>` 下新增或重命名 `.md` 时，在索引表格中 **补一行**（或按项目约定插入到合适分类），**同时**维护 **说明**（短标签）与 **提要**（较长说明），两列分工明确。用户要求按阅读顺序给 md 加 `00.` / `01.` 前缀时，走 **`rename-md-reading-order-prefix`**。
- **提要** 若有多条并列信息：在表格中仍以 **一行一格** 呈现，格内用 **`<br>`** 连接各段，保持「一条 `<br>` 前为一条提要」的维护习惯，避免整格挤成一长句。
- **同步文档内目录**：改完 `.md` 正文后，按 **`markdown-knowledge-maintain`** skill 运行 `~/.cursor/tools/md-toc/md-toc` 补充 `## 目录`（已有目录时只追加缺失章节，禁止整段重写；**默认纯 Markdown**，勿插入 HTML 锚点/回链）。
- 用户要求把一篇长文**拆成多篇**时，先按 **§7** 定切分，再改索引与前缀；禁止按原文 `##` / `###` 一节一个文件。

## 6. 阅读顺序

- **优先遵从该索引内**写明的总览文或「建议阅读顺序」；若无，则按任务关键词匹配 **说明** 列，再读 **提要** 与正文。

## 7. 拆分长文

用户说「拆分此文档」「拆到某目录」「按主题拆开」时适用。数字前缀走 **`rename-md-reading-order-prefix`**；目录与索引走 **`markdown-knowledge-maintain`**。

**需要合理拆分章节，避免机械式按原有结构切分，同时确保不丢失任何内容。**

### 7.1 怎么切

- 按**读者会问的一个问题**或**同一条通路/同一组易混名**成篇，不按原文 `## 0`、`## 1`、`### 2.1` 的目录树一节一篇。
- 原标题只是候选边界，不是文件清单。十几行、无法单独回答一个问题的残片，必须并进相邻主题（用篇内小节，不要为了「对应原编号」单独成文件）。
- 主题单一且本身已经够读（例如一整章中断）可以保持一篇，不必再按 `###` 切开。
- 两件名字像、读者会捆在一起的事（例如 AXI-Stream / MM / Lite）放同一篇对照；另一类问题（例如 CPU 摸 BAR、中断源）另开篇。

### 7.2 不丢内容

- 正文、表格、图、代码块、结论句**原样迁走**。允许改标题层级、合并进新 H1、改交叉引用；禁止为「好看 / 短文件」删段、缩写或改事实。
- 拆完后应用索引或篇首说明「按主题重组，正文未删」。合集原文件若已迁空则删除，避免双份真源。
- 迁走后立刻改同库与跨目录链接；旧锚点对不上时改到新文件（或新文件内对应节），不要留下死链。

### 7.3 拆完还要做

1. 该目录 `00._INDEX_.md`（或 `_INDEX_.md`）按 **§3** 重写读法与表格行，使之匹配新篇而不是原文章节号。
2. 文件名英文词干反映**新主题**，再按阅读顺序加 `00.` / `01.` 前缀。
3. 知识库根索引若曾指向合集单文件，改为指向专题索引，并更新 **说明** / **提要**。

### 7.4 借口对照

| 借口 | 实际 |
|------|------|
| 按原目录一节一篇最快、也最不容易漏 | 会得到无法独立阅读的残篇；漏不漏靠迁正文核对，不靠保留原编号 |
| 短节单独成文件方便深链 | 并进主题篇，用节内标题锚点 |
| 重组等于改写，不改就只能按原结构切 | 只改归属与标题层级，不改事实 |
| 用户说了「按照数字前缀命名」就是按原 `## 1` `## 2` 出文件 | 前缀是阅读顺序，切分仍按主题 |
