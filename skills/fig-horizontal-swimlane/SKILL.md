# 深彩色水平泳道图

左栏写角色/模块，横向色带分道，步骤落在对应行，时间从左到右。同列上下箭头是跨层交接。
**软件栈默认：应用层在上、硬件层在下。** 下发（调用）同列向下，上报（中断/完成）同列向上。

整个底色使用深彩色配色方案，以便适合在暗色主题环境中查看，同时保持良好的对比度和可读性。
**转成飞书画板时不要原样贴深底**：白底画板走 `markdown-to-feishu-doc` 的浅色映射（浅道带 + 饱和节点 + 深色左栏字），Markdown 源图保持本表深色。

不确定是不是这种图 → 先读 `diagram-style-catalog`。从「画流程图」进来的 → 以 `mermaid-flowchart-layout` 的 `choose-diagram.md` 为准；命中本 skill 就不要再写 `flowchart`。
交卷：写入目标 `.md` 的**内联 SVG**（开标签同一行、内部无空行；对照 `01.object-graph-and-lifetime.md`）。禁止用 Mermaid `flowchart` / `gantt` / `sequenceDiagram` 硬凑。禁止改 PNG / `![](图)` 迁就预览。

**新加 ≠ 替换。** 用户说「新加一个水平泳道图」「再加一张」时，旧图全部原样保留，只在其后（或指定位置）插入新图。禁止覆盖、删除、注释掉、并进旧图。只有用户明确说「改这张 / 替换 / 删掉旧图」才动已有 `<svg>`。

## 何时用 / 不用

| 用 | 不用 |
|---|---|
| 一条因果链穿过 2 个以上模块/进程/层次 | 顶栏 + 列内步骤、时间向下 → `fig-vertical-swimlane` |
| 读者要先看「谁的道」，再看时间 | 贴顶生命线消息 → `html-sequence-swimlane` |
| 对照 BPMN：左栏名、横线、同列下落 | 人员排期/人力胶囊 → `task-assignment-timeline` |
| 完成中断、作业、回调谁消费 | 职责墙/跨层关系网 → `mermaid-flowchart-layout` |

## 层序（硬规则）：应用在上、硬件在下

读者顺着**自己发起的调用**往机器里走：先看见应用，再进库 / 内核，最后才到硬件。
「下落」必须等于下发，不能和图上的上下对着干。

| 上 → 下（默认） | 为什么 |
|---|---|
| 应用 / 业务 | 读图的人从这里出发 |
| API / 用户态库 | 公开入口，仍是调用方进程 |
| OS 适配 / 内核 | 越往下特权越高、离 CPU 指令越远 |
| 板卡 / FPGA / 外设 | 被调的终点，不是故事的开头 |

因此：

- **下发**（open / ioctl / MMIO / 置 `RUN`）：箭头**向下**，指向硬件。
- **上报**（MSI、完成、回调唤醒）：箭头**向上**，回到应用；用虚线。
- 左栏上→下与调用栈一致，不要做成「海报式」硬件贴顶。
- 图前读法第一行写明「应用在上、硬件在下」。

用户当场指定别的层序（例如只要内核↔FPGA）时以当场为准。未指定时禁止硬件在上。

对照 `device-manager-ipc-hal-feasibility.md` §10.1 / §4.1 / §4.2 时，只学排线、分轨、单链，**不要抄那些图把硬件画在第一道**（那是旧层序）。

## 几何（截图式样）

软件栈时角色 A = 应用，角色 D = 硬件：

```
┌ 实际含义标题 ─────────────────────────────────────────┐
├────────┬─────────────────────────────────────────────┤
│ 应用   │  (起) 步骤                                    │
│ API    │        [步骤] ──→ [步骤]                      │
│ 内核   │                         [步骤]                │
│ 硬件   │                              (止) 步骤        │
└────────┴─────────────────────────────────────────────┘
```

- **标题**：图顶 40px 栏里必须有**可见**短句（`<text>`），与 `<title>` 同文。取最近小节 + 图意，无句号。禁止「流程图」「如图」「示意图」「水平泳道图」。只写无障碍 `<title>`、图上看不见 = 未完成。
- **左栏**：每道一个**层/角色**短名（单行）。左侧再加 6px 饱和色条。左栏回答「谁的道」：`用户应用层`、`API 接口层`、`内核驱动`。禁止把 `api.cpp`、`xdma_api_static.h`、`reg.h`、路径、扩展名写进左栏。文件名只写在道内节点主题。同一库内仍按层分道（实现 / 适配 / 硬件定义各一道），不要并成「用户态库」一行把层吃掉。
- **横带**：等高（默认每道 100px）。外框 + 横线 + 左栏竖线。
- **时间**：左 → 右。同一时刻的跨层交接画在**同一列**；下发竖直向下，上报竖直向上。
- **同道内推进**：水平箭头。
- **节点**：一律圆角矩形（`rx="6"`）。不要椭圆，不要把起止画成圆。主题一行，注释一行。
- **注释放在括号内**：第二行必须是 `（补充描述）`，用中文括号。不要无括号的副标题，不要把注释写进主题同一行。
- **边标签**：紧贴箭杆。竖箭头写在杆右侧约 8px，水平箭头写在线上方约 10px，垂直对齐该段中点。不要把字对齐到节点右缘（会和箭杆空出一截）。机制如 `MSI / MSI-X`；约束如 `不是函数指针`。
- **箭头**：竖轨 ≥ 2 时**颜色分轨**（见表「轨色」），**线型分语义**：实线下发、虚线上报；同层转交跟所在轨色、实线。旁路跟源轨同色。单轨仍用下发 `#3370FF` / 上报 `#00A870` / 同层 `#06B6D4`。无这三类语义时 `#E8EAED`。箭头顶和边标跟该段 `stroke` 同色。禁止多轨还一律蓝。

列数跟步骤走，不要为「好看」补空列。无决策菱形就不要硬加。

## 列与跨层（硬规则）

**先列表、再摆框、最后画 `path`。** 禁止边画节点边猜 x。

| 规则 | 做法 |
|------|------|
| 列心 | 每列写 `cx`；该列所有 `rect` / 主题 `text` 的 `text-anchor="middle"` 对齐同一 `cx` |
| 跨层同列 | 编排层与脚本层**同一步骤**（如「下载 artifacts」→「git pull」、`SOA`→`optgen`）必须**同一 `cx`**，编排框在上、脚本框在下 |
| 竖轨 | 跨层下发只用该列 `cx` 或预先登记的列间 `gutter` x；**禁止**竖线落在两框之间的长横线中段 |
| 长横线 | 同道推进：上一框**右缘 + 间隙** → 下一框**左缘**；中间空档够窄，不把上层节点「挤」到错误列 |
| 阶段交界 | check_out → build 这类跨 job 边：用倒 L 走列间竖轨，**不要**用一条横线跨越多列去接竖线 |

交卷前目视：任意编排层框正下方，脚本层应有对应步骤列；若竖线与横线呈 T 字且未进框 = 未完成。

## 排线（硬规则）

先列出每条边的竖轨 x，再画 `path`。合格：沿一条边能从起点走到终点，中途不与另一条同色边并排穿同一列，也不从框身穿过。**交卷项过了不算看过线。**

| 规则 | 做法 |
|------|------|
| 一链一轨 | 一条因果链独占一个固定 x。禁止两条语义边共用折线 x。 |
| 一出一边 | 一个节点多条出边：每条自己的 x。禁止扇出后并到同一条竖线。 |
| 同列只叠一链 | 同列竖交只给**同一条**因果链。另一条流要到同一框：走另一条边，不要贴着已有边并排。 |
| 列间留空 | 有旁路/侧入线时，相邻节点列之间至少约 40px。挤了就右移整列，不要把线画进框里。 |
| 接到框边 | 箭头落在目标边沿。禁止穿过框身、禁止贴框顶横穿再拐入。 |
| 最少折 | 一条边默认最多一个拐角（倒 L / 正 L）。先走到目标边的法线位置（正下 / 正上 / 正左 / 正右），再直线进框。禁止为了「算侧入」先竖到框底附近再贴边横滑（`H… V(底边) H(滑进框)`）。 |
| 先看线 | 写下 `path` 后沿线走一遍。多出来的折、贴框滑行、夹缝里的短横，读者会觉得怪 = 未完成。 |
| 两箭同一框 | 不要从同一边并排穿入。一边底/顶、一边侧，**或**一边底、一边顶。底入 = 先到框中线 x 再竖直上/下，不是贴底边滑入；该中线 x 若已被该节点出边占用，改为侧入（见「入出不共口」）。侧入 = 从框外对准那条边水平推进，不是先贴邻边再拐。 |
| 跨列下发 | 先到列间空档再竖直，最后水平进目标道上的框。不要在源节点那一道里横穿半个画布。目标在斜上方/斜下方时优先倒 L（横走到正下再竖），不要再加第三段去「凑侧入」。 |
| 一源三出 | 源节点放中列，出边左下 / 正下 / 右下。禁止源靠左再贴顶横穿到右列。 |
| 往返不成框 | 同一对节点既下发又上报：一个顶/底入，一个侧入，竖段 x 不同。禁止两条横线在源节点那一道里贴着对穿或并排。 |
| 入出不共口 | 有入有出的节点：入边落点与出边起点优先不同边（底进则侧出或顶出；侧进则可底出）。同边仅当换不了边，且 x 相差 ≥ 40px。倒 L 的竖段 x 不得等于该目标下一条出边的竖轨——否则进底边中线、下一跳又从中线出，两箭叠成一根。 |
| 先挪节点 | 线交叉时先改列（源放中、整列右移、加列间空档），再画 `path`。只折线绕开、节点仍挤左上 = 未完成。 |

## 主链 + 重试回路（洁净布局）

MES / 发号 / 多角色审批等：**主流程从左到右占列**，**不通过则回起点**。这是读者喊「线太乱」时最常见的一类。按下列做法画，比事后折线绕开省一整轮。

| 原则 | 做法 |
|------|------|
| **主链占列** | 每列只放一个关键步骤（典型 4 列：发起 → 校验 → 定稿 → 执行）。列心 x 先定死（列间空档 ≥ 40px），整图只微调列，不要边画边挤。 |
| **列间只倒 L** | 跨道交接：从源框**出边**水平到**列间竖轨 x** → 竖到目标道 → 水平进目标框。**禁止**源框到目标框的斜线 `L` 横穿多道。 |
| **竖轨表** | 交卷前先写一列表：`gutter1=300`、`gutter2=560`… 主链每条边只用这些 x，禁止临时新竖轨。 |
| **失败走底轨** | 不通过：**不要**在主链上再画斜回起点，也**不要**为「尾号递增 / 重试」单独占一列节点（除非业务必须点名该工位）。条件写在**底边虚线回路**的边标上。 |
| **底轨几何** | 自失败节点**底边中点** `V` 到底轨 `y`（泳道区底线上方约 12–20px，低于所有节点）→ `H` 到首列竖轨 x 或起点框中点 x → `V` 进起点框（优先**左侧入**）。全程 `#00A870`、`stroke-dasharray="6 4"`。 |
| **底轨与主链分离** | 底轨水平段 `y` 恒定在泳道底带；主链竖轨与底轨水平段**不共用**同一段 x 上的重叠（避免绿虚线与蓝实线叠一根）。 |
| **通过仍走主链** | 校验通过：出边仍用列间竖轨到下一列（可上到上一道），标签写「通过 / 定稿后」，与底轨语义分开。 |

底轨 `path` 模板（坐标替换为当图列 x、底轨 y、框边）：

```
M {cx_fail} {bottom_fail} V {y_bus} H {x_gutter_or_start} V {y_enter} H {x_start_edge}
```

合格心智图（列 = 时间，道 = 角色）：

```
[起]列1 ─gutter─↓                                
              [校验]列2 ─gutter─↑→[定稿]列3 ─gutter─↓
                                              [止]列4
列2底 ━━━ y_bus ━━━━━━━━━━━━━━━━━→ 列1侧入（虚线，仅失败）
```

交卷前七条都要过（任一条否 = 未完成）：

1. 没有线穿过框身。
2. 没有两条同色边在约 50px 内平行穿过 2 道以上。
3. 源节点那一道里没有两条横线贴顶对穿。
4. 竖轨 ≥ 2 时，最长竖段上有 `左轨 ·` / `中轨 ·` / `右轨 ·`，且各轨 `stroke` 不同（抄轨色表）。
5. 没有贴框边滑行，没有为凑「侧入 / 两箭不同边」多出来的折。
6. 每个有入有出的节点：入边落点与出边起点不在同一边的同一 x（差 < 40px 算同一口）。
7. **箭头**：语义边条数 = `polygon` 枚数；倒 L / 折线只在**进目标框**一枚三角，转角无三角；杆末端与三角底边共点、顶点落框边，无台阶（见「箭头（硬规则）」）。

有**重试 / 筛检不通过**时再加两条（任一条否 = 未完成）：

8. 失败回路只走底轨，不穿过主链节点区、不与主链水平段贴顶对穿。
9. 未为纯排线目的增加可合并进底轨边标的节点（如「尾号递增」）。

对照：一源三出中列 → §4.1；多出边分轨 → §4.2；单链 → §10.1（均在 `device-manager-ipc-hal-feasibility.md`）。主链四列 + 底轨回路 → `why-dsg3e281300019-cannot-sign.md` 第 4.2 节泳道（发号前四因数筛检）。

## 多轨轨名（硬规则）

竖轨 ≥ 2 条时，图上必须能读出轨名。只写在图下说明、不写在线上 = 未完成。单条因果链不要硬加「左轨」。

边标形状：`左轨 · <短名>` / `中轨 · <短名>` / `右轨 · <短名>`（超过三条用 `第N轨 · <短名>`，或业务短名如 `树轨 · 查树`）。贴在该轨**最长竖段**杆右侧约 8px、落在空带上，不要压进节点。字色等于该段 `stroke`，且等于轨色表。

步骤边标仍保留（如「查树」「下发通道」）。轨名加在长竖段上，不替代步骤字。

旁路边标只写动作（如「交 IPC」「收回」）。禁止把「夹缝」「侧入」写上图——那是排线，不是业务含义。从框侧进入只约束 `path`，不进边标。

对照：§4.1（左轨 · 查树 / 中轨 · 作业 / 右轨 · 事件）；§4.2（左轨 · Lite / 中轨 · 提交作业 / 右轨 · ISR）。

**图前读法**：紧挨 `<svg>` 之上的读图说明（几何、轨名、色条、线型，以及「只画…」这类贴图导语）各占一行，全部放进**同一个** `<p style="line-height:1.55;margin:0.4em 0;">`，行间用 `<br>`。行数不限四行。禁止这些行之间空成多段——预览和飞书会把段距拉得很大。正文论证段不要塞进这个 `<p>`。`</p>` 后空一行再接 `<svg>`。有则各占一行：

1. 左栏是谁。应用在上、硬件在下。时间从左到右。同列向下是下发，向上是上报（及同道推进）。
2. 图上轨名带颜色：…（竖轨 ≥ 2 才写）
3. 左栏色条：…
4. 实线是下发，虚线是上报；线色跟轨走（单轨写该图箭头说明）。
5. 有重试时：主链沿列间竖轨；不通过走底部虚线回路，不与主链交叉（仅此类图写这一行）。

**左栏色条**图注：`左栏色条：` 后面每个「X是…」分句整句包 `<span>`，用亮色（暗底可读）。禁止只给「蓝」「紫」一个字上色，禁止用节点 `fill` 那种偏暗饱和色当正文。色条写**归属/身份**，不写文件清单。同一份软件的多道同色：`橙是同一用户态库`。合格：`蓝是业务` / `绿是 Manager` / `紫是用户态库`。禁止：`蓝是应用与寄存器头`、`橙是 api.cpp 与 FPGA`（跨层拿文件拼色）。

| 分句 | 亮色 |
|------|------|
| 蓝是… | `#7DD3FC` |
| 紫是… | `#D8B4FE` |
| 绿是… | `#6EE7B7` |
| 橙是… | `#FBBF24` |
| 红是… | `#FB7185` |

## 新加（硬规则）

「新加一个水平泳道图」= 文档里**多一张**，不是改旧那张。

| 用户说 | 做 |
|--------|----|
| 新加 / 再加一张 / 再画一张 / 保留旧图 | 已有水平泳道 `<svg>` **全部原样留下**；新图插在后面或用户指定位置 |
| 改这张 / 替换 / 删掉旧图 / 把这张改成 | 才编辑或删除指定的那一张 |

禁止把「文档里已经有泳道」理解成「更新那张」。一张 md 可以有多张水平泳道，每张独立 `<svg>` + 自己的图前读法。

## 媒介

1. 用户点了 `.md` 里**某一张**要改媒介 → **只把那张**换成内联 `<svg>`（`viewBox` 固定，`max-width` 100%）。同页其它图不动。
2. 有 `ai.cursor/` 时路径走 `ai-cursor-doc-output`。
3. 不要另存 PNG，不要 `![](….png)` / `![](….svg)`，不要 sidecar 图文件来迁就预览。预览空白时修开标签单行与内部无空行（对照 `01.object-graph-and-lifetime.md`），不要改媒介。不要为了「像 Mermaid」再留一份 subgraph。交卷跑 `audit_mermaid.py`（`svg-blank` / `svg-open-split` / `swimlane-png`）。
4. `<title>` 与顶栏可见标题同文；短句、无「流程图/如图」。
5. 同页多张泳道时，`polygon` / `path` 不用跨图共享 id；**不要**为箭头堆 `<defs><marker>`（见「箭头（硬规则）」）。
6. 泳道本体放在 `translate(0,40)` 里，`viewBox` 高度 = 泳道高 + 40。
7. `<svg>` 到 `</svg>` **之间禁止空行**（CommonMark 截断 HTML，节点变源码）。分组用 `<!-- -->`。开标签同一行。交卷跑 `audit_mermaid.py`（`svg-blank` / `svg-open-split` / `swimlane-png`）。
8. 用户要飞书画板：深色源 SVG 只给 MD 预览；导入/修已有画板用 `markdown-to-feishu-doc`（浅色化）。禁止为迁就飞书改掉 `.md` 里的暗色图。

## 箭头（硬规则）

写入 `.md` 的内联泳道图，**禁止 `marker-end` / `marker-start`**。Cursor / VS Code Markdown 预览里 `refX` 与路径终点常错位，竖线上会出现「台阶」或三角悬空。

每条有向边画**两件**（同色）：

1. `path` 或 `line`：`stroke-linecap="butt"`，终点停在**箭头底边**（距目标框边约 8px）。
2. 紧挨其后的 `polygon`：顶点贴在目标框边沿，底边与线段终点共点。

模板（向下进框顶 `y=框顶`，向右进框左缘 `x=框左`）：

```svg
<path d="M200 72 V 120" fill="none" stroke="#3370FF" stroke-width="2" stroke-linecap="butt"/>
<polygon points="200,128 196,120 204,120" fill="#3370FF"/>
<path d="M245 150 H 278" fill="none" stroke="#06B6D4" stroke-width="2" stroke-linecap="butt"/>
<polygon points="286,150 278,146 278,154" fill="#06B6D4"/>
```

| 情形 | 箭头 |
|------|------|
| **同道两框**（水平一跳） | 短线 + 一枚 `polygon` |
| **倒 L / 多段折线**（同一语义边，跨道或列间轨） | **一条** `path`（`stroke-linejoin="miter"`）+ **仅在进目标框** 一枚 `polygon`；转角**不要**箭头 |
| **底轨回路** | 全程一条 `path`，只在进起点框一枚 `polygon` |

禁止在折线每个直角各画一枚三角（读者会看到「三根箭头」）。

「主链四列 + 底轨」骨架里的 `marker` 仅作坐标参考；**复制进目标 `.md` 交卷前**须把读者能看见的箭头全部换成上表写法。对照同仓库 `fig-side-by-side-flowcards`「箭头」节。

## 工作流

1. 列出左栏**层/角色**（上→下：应用在上、硬件在下）。先写层名，再把文件落进该道节点。禁止用源文件当左栏。同一库多层：左栏分道，色条同色归成一家。
2. 列出步骤：谁、主题、括号注释、落在第几列；**跨层步骤标同一列 cx**。一个节点 ≥ 3 条出边，或既下发又上报回同一源：该源先放中列。**有重试**：主链按列排，失败逻辑写底轨边标，不为「递增 / 重试」单列加框。
3. 先写**列心 cx** 与**列间竖轨 x** 表（含跨层同列），再按表摆框，再定底轨 `y`（有回路时）。画 path：主链只用倒 L；回路只用底轨一条 path。竖轨 ≥ 2 时在最长竖段写轨名。每个节点记下入边落点与出边起点，禁止相同。
4. 按上表上色；注释全部加 `（）`。有向边用 **线 + `polygon`**，不用 `marker`。**一语义边一枚箭头**。走「排线」交卷前七条 + 有回路时再加 8–9 条；沿每条边看多余折、两箭共口、转角三角、主链与底轨交叉、箭头台阶，不过就改线或右移列。
5. 写入目标 md；图下补色名图例（若用了色名）。**新加**时不要改动已有 `<svg>` 块；只追加新图及其图前读法。
6. **用户说箭头错位 / 没箭头 / 衔接不对**：先核列心表与「一语义边一箭」，再改 `path` 终点与那一枚 `polygon`。禁止在旧折线上每段加三角，禁止只改 `marker` 不改几何。列挤了就**整列按表重摆**，不要在旧坐标上打补丁。
